# 相对定位与文字片段

`position: relative` 的视觉偏移进入布局帧、绘制、圆角和裁剪、文字范围、指针命中、选区、光标及 AX 几何。定位声明与 margin 使用不同的私有字段，公开 C ABI 没有增加第三方类型或新导出。

支持物理四边 `top/right/bottom/left` 和一至四值 `inset`；值包括 auto、百分比、已有绝对/字体/视口长度和线性 calc。简写、长属性、important、层、revert/revert-layer、变量替换及无效计算值继续由同一层叠入口决定。显式 inherit 继承计算后的绝对长度与未解析百分比，不在后代重新计算父元素的 em。水平百分比按包含块宽度，垂直百分比在包含块高度不确定时按 auto 处理；双边均指定时，上边优先，水平方向由包含块的 direction 决定。

block、Flex/Grid 项目和原子 inline 先完成原有正常流求解，再移动视觉子树；兄弟位置、排版尺寸、基线和行高保留正常流结果。普通 inline 不被转成原子盒，仍跨 DOM 节点整形和换行，嵌套偏移累加。段落保存布局之后的文字片段偏移，glyph、背景/边框、圆角、UTF-16 范围、光标和命中共享偏移；原子内容使用原场景和段落对象的实际位置，避免重复绘制。

溢出计算同时保留原正常流范围和视觉范围。相对移动可以扩大滚动范围，不会因向左/上移动而丢失原本的正常流占用。裁剪与滚动口跟随外层相对位置；纯滚动继续使用保留投影，不增加 layout_frames。位置变化产生旧新损伤，静止帧继续复用。相关操作归 Runtime UI 线程，纯盒定位不触发资源解压或启动 worker。

`document.position` 从公开 SDK 验证四边与简写、变量/继承/层、RTL、Flex/Grid、嵌套及跨行 inline、原子内容、原正常流溢出、圆角指针、选区/光标和 AX。跨行文字加矩形边框后的整帧像素，与未定位画面的整数平移逐字节一致；包括圆角的动态保留画面与新建 View 的完整绘制另行比较。滚动后的画面与相同偏移的完整重排比较，同时断言布局次数不变。静态 SDK 和真实内置 SwiftShader 复用同一组行为测试。

Windows SwiftShader 的独立平移测量中，矩形边框全图无差异；3px 圆角的跨行边框出现18个通道差异，最大31/255，CPU同例无差异。差异位于圆角抗锯齿边缘，记录于阶段 swift-translation.json，不声称该后端的曲线覆盖率对整数平移逐字节不变。圆角在同一最终位置的保留绘制、全量重排及新 View 完整绘制仍要求逐字节一致，没有放宽这些正确性检查。

相对偏移及其共同几何与后续实现的z-index/层叠上下文共同工作，绘制与命中顺序见stacking.md。`absolute/fixed/sticky` 的语法和计算声明已可识别，但其脱流、包含块、滚动约束与绘制行为仍未实现，继续计入 unsupported；这些模式不能用本阶段包当作已支持。逻辑 inset/垂直书写、transform/translate、anchor positioning、完整数学函数、完整 inline box-decoration-break:slice 和全部现代 CSS 仍在总计划内。Win7、旧 Linux、macOS/Web 的实机验收继续单列，本机 Debug 检查不代替这些平台证据。
